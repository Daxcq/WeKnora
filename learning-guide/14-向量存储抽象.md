# 第 14 章 · 向量存储抽象：11 种引擎一个接口

## 14.1 类型系统：`internal/types/retriever.go`

两个维度的常量：

**引擎类型**（存到哪家向量库）：

```go
postgres / elasticsearch / infinity / elasticfaiss / qdrant / milvus /
weaviate / doris / sqlite / tencent_vectordb / opensearch
```

（`internal/container/engine_factory.go:62-78` 的 switch 按这些常量实例化对应引擎。）

**检索类型**（这一路检索用什么方法）：

```go
KeywordsRetrieverType   "keywords"   // 关键词（倒排索引）
VectorRetrieverType     "vector"     // 向量（embedding）
WebSearchRetrieverType  "websearch"  // 联网搜索
```

**认知**：引擎与检索方法是**正交**的——pgvector 可以同时做 vector 和 keywords 检索（ParadeDB 扩展），Milvus 只做 vector，ES 天生擅长 keywords。混合检索 = 同一引擎（或多个引擎）跑多条 RetrieverType。

## 14.2 统一接口：`RetrieveParams` 与结果

所有引擎吃同一份参数（`types/retriever.go`）：

```go
type RetrieveParams struct {
    Query        string      // 查询文本
    Embedding    []float32   // 查询向量（vector 检索用）
    KnowledgeBaseIDs []string
    TagIDs, ExcludeKnowledgeIDs, ExcludeChunkIDs []string  // 过滤
    TopK         int
    Threshold    float64
    KnowledgeType string     // "faq"/"manual"——决定用哪个索引
}
```

返回统一的 `SearchResult`（含 ID、Content、Score、ChunkType、ParentChunkID、PreChunkID/NextChunkID……）——读路径的 merge_expand 就靠最后这两个邻居 ID 做扩展。

**接口的社会学**：11 家向量库的 SDK 千差万别（建索引语法、过滤语法、距离度量全不同），但 WeKnora 上层只见这一个接口。新增引擎 = 在 `internal/application/repository/retriever/` 下加一个包实现接口 + engine_factory 加一个 case。

## 14.3 工厂：`engine_factory.go`

```go
func NewEngineFactory(db *gorm.DB, cfg *config.Config, ...) interfaces.EngineFactory {
    return func(ctx context.Context, store types.VectorStore) (interfaces.RetrieveEngineService, error) {
        ...switch store 的引擎类型...
    }
}
```

工厂返回**闭包**（第 3 章：函数是值）——调用时才根据"这个知识库配置的向量库"实例化引擎。每个引擎的创建函数负责：建连接、确保 collection/index 存在、映射字段。

选库方式：知识库配置里指定 VectorStore（UI 可配，`vector-store.ts` API 管理），环境变量 `RETRIEVE_DRIVER` 提供默认。

## 14.4 组合层：混合检索

引擎之上还有一层编排（`internal/application/service/retriever/`）：

- `composite.go`——组合多个 retriever（vector + keywords）；
- `keywords_vector_hybrid_indexer.go`——写入时同时维护两种索引；
- `registry.go`——检索器注册表。

第 2 章的"两路失误互补"在这里落地：查询进来 → composite 分发给 vector 路（Q.Embedding → 相似度 Top-K）和 keywords 路（Q.Query → 倒排匹配 Top-K）→ 结果融合（RRF 思想：比排名不比绝对分）→ 交给 chat_pipeline 的 search 插件。

## 14.5 选型速查

| 场景 | 推荐 | 理由 |
|---|---|---|
| 单机/轻量 | sqlite（sqlite-vec）或 postgres（pgvector） | 零额外部署 |
| 已有 Postgres | pgvector | 复用现有 DB |
| 大规模+高性能 | Milvus / Qdrant | 专用 ANN 引擎 |
| 已有 ES 且重视关键词 | Elasticsearch/OpenSearch | 倒排+向量一体 |
| 国产云 | 腾讯向量数据库 | 托管 |

**对学习的意义**：不必通读 11 个实现——精读 `postgres/`（最常见）+ 扫一眼 `milvus/`（对比专用引擎差异）即可，其余是同一接口的不同方言。
